# Changes since the initial import

This file records what changed between the first commit (`1ca0f6f`, "Inital project import", 2026-10-28) and
`main` today (`1e94915`, merge of PR #10, 2026-10-29). It is a map of the work, not a replacement for the commit
history; every item below can be traced to a commit or pull request.

The commits after the import were made with Claude Code at the repository owner's direction; the commit messages carry
the co-author line and the pull requests were merged by the owner.

**Size of the change:** 909 files, +19,812 / −1,808 lines. Most of that is data, not code: 644 cached LLM responses,
97 evaluation sources (30 dev + 67 test) and their 97 published copies. Two files were removed, none of the original
application modules was deleted.

## What the project was at the start

The initial import was a working prototype with a technical-specification README:

- FastAPI backend (`/health`, `/review`, `/stream`), LangGraph fan-out of three Gemini specialists plus a synthesizer,
  four static analysers (Semgrep, Bandit, Ruff, ESLint), a React + Vite + TypeScript client.
- A 30-file evaluation (`evaluation/samples`, `ground_truth.json`) generated by `prep_dataset.py`.
- A `vercel.json` for deployment and an unpinned `requirements.txt`.
- No tests, no Docker, no CI, no license, no request limits.

## 1. Pipeline bugs fixed (`server/`)

Each of these was a silent failure: the API returned a normal-looking answer that was wrong.

| Bug | Effect | Fix |
|---|---|---|
| `tool_runner` never passed the language to Semgrep | JavaScript was scanned with the Python rules | Language is passed through |
| ESLint called with `--no-eslintrc` (removed in ESLint 9) | ESLint failed on every call and the error was swallowed into an empty list | Invocation fixed; failures are reported |
| Semgrep fetched its rules from the registry on each request | A blocked registry silently disabled Semgrep | Rules ship in `server/rules/` (`python.yml`, `javascript.yml`); registry packs are opt-in via `SEMGREP_EXTRA_CONFIGS` |
| Synthesizer only emitted issues the LLM placed in a merged group | Every other specialist issue was dropped | Unclaimed issues pass through; an index belongs to one group only |
| An unparseable synthesizer response skipped the retry loop | One malformed reply lost the whole review | Parse failures are retried |
| Any agent or tool failure returned HTTP 200 with zero issues | Indistinguishable from clean code | Failures appear in `ReviewResponse.warnings`; `/review` returns 502 and `/stream` emits `error` when every specialist fails |
| `normalize()` crashed with HTTP 500 on a JS syntax error | ESLint's `ruleId` is null for parse errors | Handled |
| `prefer-const` / `no-var` classed as performance rules; no Python performance tool | Wrong categories, no performance signal for Python | Reclassified; Ruff `PERF` rules now feed the performance agent |
| `/stream` ran subprocess calls on the event loop and handled only the first node of each LangGraph chunk | Blocked the server; dropped events | Offloaded; every node is handled |

Refactors made along the way:

- The three specialist agents were near-identical copies; they now share `server/agents/base.py`.
- All Gemini access (retries, JSON extraction, temperature 0, JSON mime type, `GEMINI_MODEL` override) lives in
  `server/llm.py`. Truncated model output is rejected and retried, not repaired into a half-finished `fixed_code`.
- `server/pipeline.py` is shared by the API and the evaluation, so published numbers come from the code that serves requests.
- The client shows `warnings` and handles the new `error` stream event.

## 2. Evaluation rebuilt (`evaluation/`)

The original evaluation could not support a claim, for these reasons:

- Labels were generated from the CWE in each filename plus a regex guess at the line, then described as hand-labeled.
- Filenames like `018_CWE-089_codeql_1_py.py` were sent to the model, leaking the answer.
- One label per file and no clean files, so precision and false-alarm rate could not be measured.
- Matching used substrings and a synonym map; there were no baselines; the data was a public benchmark.

What replaced it:

- **Labels** are `@label <class> <severity>` comments in annotated sources (`dataset/src`). `build_dataset.py` strips
  them without moving lines and publishes neutrally named copies in `samples/`. All 30 original files were re-read and relabeled.
- **A held-out `test` split** of 67 files written for this project: 56 labelled issues, 14 clean (hard negatives).
  The original 30 files became the `dev` split. 49 files were added first, then 18 harder ones (`2fa4e82`) using
  Django, FastAPI, Flask and Express and more safe look-alikes. The "SSTI → code_injection" taxonomy mapping was added
  before any LLM system had been run.
- **Strict scoring** (`scoring.py`, `taxonomy.py`): a prediction counts only if file, category and one of 21 closed
  classes match a label within ±3 lines, one-to-one. Duplicates, ambiguous labels and clean-file false alarms are
  reported separately.
- **Four systems** (`systems.py`): `tools_only`, `single_llm`, `multi_agent_no_tools`, `multi_agent`.
- **Metrics** (`compute_metrics.py`): precision, recall and F1 with 95% bootstrap intervals over files, clean-file false
  alarms, severity accuracy, per-class recall, unmapped names.
- **Reproducibility** (`llm_cache.py`): every Gemini response is cached on disk, keyed by model, prompt and input.
  `--offline` replays without a key or network; `--resume` continues a partial run.
- **Failures never count as "found nothing"** (`records.py`): a file where any agent failed is recorded as failed and
  excluded. The synthesizer's fallback counts as a failure. A per-day quota error stops the run cleanly (exit code 2).
  Gemini's per-minute 429 is waited out instead of retried inside the blocked window.
- `sensitivity.py` is a diagnostic added later: it drops every finding the closed vocabulary cannot classify, from
  every system, to test whether the ranking depends on that choice. It does not.
- `evaluation/README.md` documents the protocol and the threats to validity.
- `prep_dataset.py` was deleted; `build_dataset.py` replaces it.

## 3. Results (`evaluation/results/`)

The paid-key run was completed for all four systems on the 67-file test split. The result is negative for the
multi-agent design:

| system | precision | recall | F1 | clean files with a false alarm |
|---|---|---|---|---|
| `tools_only` | 0.68 | 0.68 | 0.68 | 4 / 14 |
| `single_llm` | 0.59 | 0.84 | 0.70 | 12 / 14 |
| `multi_agent_no_tools` | 0.22 | 0.73 | 0.34 | 14 / 14 |
| `multi_agent` | 0.25 | 0.79 | 0.37 | 14 / 14 |

One prompt matches the static tools, and the pipeline is worse than both because it reports many false positives.
A replay of the committed cache reproduces every prediction (4 systems × 97 files, 0 differences). Intervals,
per-class tables and every false positive are in `RESULTS.md` and `errors.md`. The cause of the noise is untested.

## 4. Packaging and abuse protection

- **`server/limits.py`** (`RequestGuard`, `Ticket`): per-IP sliding-window rate limit, a daily global budget (UTC), a
  code size cap and a concurrency cap. Configured by `MAX_CODE_CHARS` (20000), `RATE_LIMIT_PER_MINUTE` (6),
  `DAILY_REVIEW_BUDGET` (100), `MAX_CONCURRENT_REVIEWS` (3); `0` disables each. `TRUST_PROXY_HEADERS` uses the last
  `X-Forwarded-For` entry, which a client cannot choose.
- **`server/main.py`**: `/review` and `/stream` pass through the guard; CORS origins come from `CORS_ORIGINS`
  (default `http://localhost:5173`); the built UI is served from `client/dist` or `STATIC_DIR`.
- **Docker**: one multi-stage image (node build stage, node ESLint stage, `python:3.12-slim`), non-root, listens on
  `$PORT`, no secrets baked in. Plus `.dockerignore`, `docker-compose.yml`, and a `Makefile`.
- **Dependencies pinned** in `requirements.txt`; test dependencies in `requirements-dev.txt`; `.env.example` added.
- **CI** (`.github/workflows/ci.yml`): server and evaluation tests with the real analysers, dataset checks, client build,
  and an image smoke test (`scripts/smoke_test.sh`) that runs with no API key.
- **Client**: `client/src/api.ts` adds `API_BASE` (`VITE_API_BASE`) and `errorMessage()`; `ProgressPanel` uses them.
- **`vercel.json` removed**: the app is now one container.

## 5. Deployment

`render.yaml` is a blueprint for the Docker image. The app is live at https://code-review-v2i1.onrender.com on
Render's free tier, which sleeps when idle (first request up to a minute) and takes about 30 seconds per review.

## 8. Known limitations left in place

- The evaluation is small and synthetic: one labeler, 67 files, one run per system, a small model, and labels and
  static rules share an author.
- TypeScript files are routed to the JavaScript path and produce parse errors.
- Rate limits are in-memory, per process.
- The specialist prompts still describe the performance agent as receiving only ESLint findings, although Ruff findings now
  reach it. They were left alone on purpose: any edit invalidates the evaluation cache.
